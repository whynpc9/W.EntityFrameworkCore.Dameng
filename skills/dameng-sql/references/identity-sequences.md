# 自增列与序列

达梦有三种「自动给号」方式。生成 SQL 时先选定一种，不要混用，也不要套 SQL Server 的 `NEXT VALUE FOR` 或 PostgreSQL 的 `GENERATED BY DEFAULT AS IDENTITY` 原文。

## IDENTITY

```sql
CREATE TABLE app_user.orders (
  id   INT IDENTITY(1, 1) NOT NULL,
  memo VARCHAR(256),
  CONSTRAINT pk_orders NOT CLUSTER PRIMARY KEY (id)
);

INSERT INTO app_user.orders (memo) VALUES ('A');
COMMIT;
```

回读：

```sql
SELECT SCOPE_IDENTITY();                 -- 当前作用域
SELECT IDENT_CURRENT('APP_USER.ORDERS'); -- 指定表
SELECT @@IDENTITY;                       -- 会话内最近一次
```

在存储过程里，`SCOPE_IDENTITY()` 可能拿不到值（作用域是模块/批）。需要会话级最近值时用 `GLOBAL_IDENTITY`：

```sql
CREATE OR REPLACE PROCEDURE app_user.cs
AS
BEGIN
  INSERT INTO app_user.cs2(name) VALUES ('1');
  SELECT GLOBAL_IDENTITY;
END;
/
```

显式写入 IDENTITY 列：

```sql
SET IDENTITY_INSERT app_user.orders ON;
INSERT INTO app_user.orders (id, memo) VALUES (100, 'manual');
```

文档说明：`SET IDENTITY_INSERT ... ON` 后会自动回到 OFF，且只影响当前会话。未打开时对 IDENTITY 列赋值会报 `-2723`。

不能通过 `ALTER COLUMN` 把普通列改成 IDENTITY，或改种子/增量；需要重建列或改用序列 / `AUTO_INCREMENT`。可用 `ALTER TABLE ... DROP IDENTITY` 去掉 IDENTITY 属性。

主键为 IDENTITY 时，插入 `0` 可能查不到该行（内部把 0 当成未赋值）。不要依赖「插入 0 再按 0 查询」。

## AUTO_INCREMENT

更接近 MySQL，必须落在唯一约束/主键的整数列上（`TINYINT` / `SMALLINT` / `INT` / `BIGINT`，不是 `DEC(n,0)`）：

```sql
ALTER SESSION SET 'AUTO_INCREMENT_INCREMENT' = 6;
ALTER SESSION SET 'AUTO_INCREMENT_OFFSET' = 15;

CREATE TABLE app_user.t1 (
  id   INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100)
) AUTO_INCREMENT = 20;

INSERT INTO app_user.t1(name) VALUES ('implicit');
INSERT INTO app_user.t1(id, name) VALUES (50, 'explicit');
SELECT LAST_INSERT_ID();
```

相关会话参数：

| 参数 | 含义 | 缺省 |
| --- | --- | --- |
| `AUTO_INCREMENT_INCREMENT` | 步长，1–65535 | 1 |
| `AUTO_INCREMENT_OFFSET` | 基准偏移，1–65535 | 1 |
| `NO_AUTO_VALUE_ON_ZERO` | 插入 0 时是否改成下一个自增值；1=是 | 1 |

同一张表不能同时指定 `IDENTITY` 和 `AUTO_INCREMENT`。

从 IDENTITY 迁到 AUTO_INCREMENT 的典型步骤：备份表 → `ALTER TABLE ... DROP IDENTITY` → 保证唯一约束 → `ALTER TABLE ... ADD id AUTO_INCREMENT`。改之前确认 `AUTO_INCREMENT_INCREMENT` 仍是预期值。

## 序列

```sql
CREATE SEQUENCE app_user.order_seq
  START WITH 5
  INCREMENT BY 2
  MAXVALUE 200;

INSERT INTO app_user.orders_seq (id, memo)
VALUES (app_user.order_seq.NEXTVAL, 'B');

SELECT app_user.order_seq.NEXTVAL FROM dual;
SELECT app_user.order_seq.CURRVAL FROM dual;
```

这是达梦/Oracle 风格。**禁止**生成：

```sql
NEXT VALUE FOR app_user.order_seq   -- SQL Server，不要用
```

表默认值可以直接写 `app_user.order_seq.NEXTVAL`。

## 其他唯一值

```sql
SELECT SYS_GUID();          -- BINARY(16)
SELECT GUID FROM dual;
SELECT NEWID();             -- 部分兼容路径上也可见
```

## 选择建议

- 新表、EF 标识列：优先 `IDENTITY(seed, increment)` + 非聚集主键（表上还有 LOB 时必须如此）。
- 跨表共享编号、TPT/多表需要同一套号：用序列。
- 明确要 MySQL 兼容、且实例 `compatible_mode` 允许：才用 `AUTO_INCREMENT`。
