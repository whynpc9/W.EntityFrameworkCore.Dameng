## 相对 0.4.0 的变化

- 查询：修正字符串 Replace 的空值语义，补齐 LOB 集合运算与聚合排序守卫；
  改善时态 SQL 字面量保真，对无法正确翻译的时态转换器模型精确拒绝。
- 驱动与连接：补齐运行时连接、时态参数及已初始化模型的驱动一致性检查；
  HasTables 接入 EF 命令诊断、超时和拦截链，W 使用异步调用；补强故障会话淘汰证据。
- 模型：校验共享列的生成契约和复杂属性中的 rowversion，保留合法模型对照。
- 迁移：纯注释修改避免无关结构变更，修正历史表脚本的词法定位；
  补齐不确定 DDL 的精确资源恢复、迁移锁争用和释放测试。
- 反向工程：普通列目录缺失时明确拒绝不完整模型；独立 PK_WITH_CLUSTER=1
  profile 已在 M6 验证，未增加新的 LOB 主键策略。
- 测试与安全：CLI 连接配置不进入参数/生成源码，校验实际被测程序集身份，
  增加无秘密的离线 CI 和恢复状态自测。
- W 扩展包采用已合并的 `W.DamengProvider 0.3.1`，替换上一发行包的 `0.2.0`。

逐项结论与历史失败见 [M1–M6 证据索引](../plans/README.md)、
[最终二十项对账](../plans/evidence/020.md)和[兼容矩阵](compatibility.md)。

## 升级与验证边界

- .NET 10 / EF Core 10，不扩展最低服务器版本声明。两种驱动仍为单命令修改批次。
- 官方驱动七位时态参数问题仍为维护者已接受的已知风险，精确 SQL 字面量的修复
  不构成官方参数精度修复，见[风险说明](compatibility.md#预先已知的官方驱动风险时态参数精度)。
- W 默认 TLS；本地真实库验收使用显式 `PlaintextAllowed`，不作为 TLS 证据。
  W 禁止自动重试，结果未知时应从独立连接核对业务效果。
- DDL 隐式提交，不保证迁移原子回滚；不确定结果须按唯一对象名查证和恢复。
- 规范测试只有四项自有冒烟，不表示上游 EF 完整关系一致性。
- 不宣称新增 DataSource、流式 LOB、所有服务器版本/页大小、MPP 或 commit 丢失 ACK 验收。
- 本轮只调整版本与发行文档；独立 PK=1 profile 仍引用 M6 对相同产品代码的证据，
  不把它写成本轮重新运行的结果。

## 正式发布顺序

1. 复核本记录、候选包及验收结果，提交最终准备变更并完成远端 CI。
2. 在最终提交创建附注标签 `v0.5.0`，通过现有工作流发布基础包。
3. 确认 Actions、GitHub Release、NuGet 公共下载、内容和签名。
4. 在同一提交创建 `wdriver-v0.5.0-preview.1`，发布 W 扩展包。
5. 验证 W 公共包精确依赖 `[0.5.0]` / `[0.3.1]`、内容与签名，再更新发布状态。
