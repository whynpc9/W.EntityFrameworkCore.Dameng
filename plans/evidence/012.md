## 模型与修复

两个实体通过识别 PK/FK 关系共享 `APP.Shared.Id`；合法模型断言同一 ITable/IColumn 恰有两个不同属性映射。单个 DbContext 通过关闭服务提供程序缓存保证每组配置重新最终化，W 使用 `UseDamengWithWDriver` 实际服务。正反注册顺序逐项执行。

基线中 identity seed 7/11、increment 3/2、3/-3、identity/sequence、Ids/OtherIds 和 APP/OTHER 均未被锁定 EF 或提供程序拒绝，设计时关系模型可达。补充 `ValidateSharedColumnsCompatibility`，先调用基类，再按当前 store object、Ordinal 列名记录首个**有效生成器**，比较其他生成器的策略及对应分面。不能只比较原始首个映射：三属性模型首个为 None 时仍须比较后续两个生成器。异常点名双方、表/列和分面。None 没有第二个生成合同，不作为冲突；未改公共策略解析、注解提供者或生成器。

| 候选/合法对照 | 最终断言 |
| --- | --- |
| identity seed、正/负 increment | 各自 IdentitySeed / IdentityIncrement 拒绝，双方属性及表名准确 |
| identity 对 sequence | ValueGenerationStrategy 拒绝 |
| sequence name / schema | SequenceName / SequenceSchema 拒绝 |
| 相同 identity、约定共享 FK None | 一个物理列；seed=7、increment=3，None 保留 |
| 相同序列、默认/显式 APP 等效 schema | 同一 Ids、APP，实际 NEXTVAL 引用一致 |
| 三属性首映射 None | 相同生成器通过，seed冲突拒绝；两个注册顺序 |
| TPT / TPC | TPT仅根表identity；TPC两个具体表共享序列，实际设计时表数断言 |

测试方法：`SharedColumnBaselineAcceptsMatchingIdentity`、`SharedColumnBaselineAcceptsConventionForeignKeyCopy`、`SharedColumnRejectsConflictingIdentitySeed`、`SharedColumnRejectsConflictingIdentityIncrement`、`SharedColumnRejectsIdentitySequenceConflict`、`SharedColumnRejectsDifferentSequenceNameOrSchema`、`SharedColumnAcceptsMatchingSequence`、`SharedColumnAcceptsEquivalentDefaultAndExplicitSequenceSchema`、`SharedColumnOutcomeDoesNotDependOnEntityRegistrationOrderOrNoneMapping`、`SharedColumnValidationPreservesTptAndTpcGeneration`。两驱动各26例。
